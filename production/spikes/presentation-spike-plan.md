# Presentation Spike 规划 (C1)

> **创建日期**：2026-07-28
> **来源**：gate-check Pre-Production→Production CONCERN C1 + C6
> **目标**：在全面铺开 Core/Feature 层之前，用实际美术资产验证"修仙爽感"能否被传递
> **建议时机**：Sprint 2 或 Sprint 3（Foundation 层完成后）

---

## 背景

垂直切片验证了**机制可行性**——核心循环可玩、Godot 4.6 零编译错误。但试玩者明确表示"感受不到修仙爽感，UI 太差了"。

当前规划中 Presentation 层在所有 Foundation → Core → Feature 层之后才触及，意味着数月的 Production 中"修仙爽感"缺失将持续存在，无早期预警信号。

**Presentation Spike 的目标**：在投入大量 Feature 开发之前，用最小成本验证——"有了实际美术资产后，修仙爽感能否被传递？"

---

## 验证方法

### 复用垂直切片代码

Presentation Spike **不是重做垂直切片**——它是在现有 `prototypes/cultivation-card-battle-vertical-slice/` 代码上叠加美术层：

```
prototypes/cultivation-card-battle-vertical-slice/
├── assets/          ← 新增：美术资产目录
│   ├── sprites/     ← 角色立绘、卡牌插画
│   ├── audio/       ← 音效、BGM
│   └── vfx/         ← 天劫过场帧序列
├── scenes/          ← 改造：用 .tscn 场景替换程序化 UI
└── scripts/         ← 改造：接入资产 + Tweener 动画
```

> ⚠️ 仍然是原型代码标准——不迁移到 `src/`。Spike 代码仅供验证，验证完成后归档。

### 试玩验证

| 验证项 | 之前（纯程序化） | 目标（Spike 后） | 判定标准 |
|--------|:--:|:--:|------|
| 修仙爽感 | ❌ "感受不到" | ? | 试玩者独立描述出 ≥1 条与游戏支柱匹配的情感体验 |
| 天劫紧张感 | ❌ 闪烁太弱 | ? | 试玩者渡劫后自发描述紧张/释然/成就感 |
| 界面直觉性 | ✅ "一看就懂" | 保持 | 程序化 UI→资产化 UI 后不降低可用性 |
| 无引导完成率 | 100% | 保持 | 仍需 100% |

## 试玩协议

1. **最少 2 次试玩**（必须至少有 1 名非开发者）
2. 试玩后立即记录：情感反应、困惑点、最印象深刻的瞬间
3. 使用 `/playtest-report` 结构化记录

### 关键问题（试玩后回答）

1. 试玩者是否在渡劫成功时自发流露出正面情绪？
2. 试玩者能否描述出"我的修仙之路"相关的体验（即使是一句话）？
3. 试玩者是否对某张卡牌或某个角色产生偏好/厌恶？
4. 试玩者是否能区分不同品质的卡牌（仅通过视觉）？
5. 美术风格是否被认可是"修仙世界"而非"通用奇幻"？

---

## 成功标准

### PROCEED（继续）
- ≥3/5 关键问题答案为"是"
- ≥1 名试玩者独立体验到"修仙爽感"
- 渡劫过场的紧张感和突破释然感被自发提及

### ADJUST（调整）
- 2/5 关键问题答案为"是"
- 核心循环仍可玩但审美方向需要校正
- 调整美术方向后重新验证（追加 0.5 Sprint）

### RETHINK（重新思考）
- ≤1/5 关键问题答案为"是"
- 美术资产的加入没有改变情感体验
- 需要重新审视"修仙爽感"是否依赖于视觉传递——可能需要更深层的设计变更

## 不包含的内容（明确排除）

- 完整角色立绘集（仅需要 1 名主角）
- 完整卡牌插画库（仅需要 3-5 张）
- 音频系统架构设计
- VFX 粒子系统
- BGM 完整配乐（仅需要 1 条循环）
- 卡牌框体/UI 框架（复用程序化 UI）

## 调度建议

```
Sprint 1 (当前): Foundation 层完成
    ↓
Sprint 2: Presentation Spike (C1)
    ├── 前半：资产制作（立绘+卡牌+过场帧+音效）
    ├── 中：代码接入（Tweener 动画 + 音效触发）
    └── 末：试玩验证 (×2)
    ↓
Sprint 3: 基于 Spike 结果
    ├── PROCEED → Core 层启动（card-system/realm-system）
    └── ADJUST  → 方向修正 + Core 层并行启动
```

## Purpose & Player Need

**玩家到达此屏幕时想要：** 在花费灵石或放弃卡牌之前，清楚地知道「我付出什么、得到什么、我的构筑会变成什么样」。

卡组编辑 UI 服务于 Roguelike 卡牌的核心决策循环——**资源换精炼**。玩家在这里做三类有代价的选择：

| 玩家目标 | 对应界面 | 玩家幻想（GDD） |
|---|---|---|
| 「这张卡值不值得买？」——权衡价格、稀有度与构筑契合度 | 坊市-购买 | 购买的期待 |
| 「哪张卡该放手？」——付出灵石删除一张不再有用的卡 | 坊市-散功/出售 | 删卡的心痛、出售的算计 |
| 「我的构筑现在什么样？」——浏览全貌、回顾冒险历程 | 卡组浏览（含历史） | 构筑的审视 |
| 「必须舍弃谁？」——超限时的强制取舍 | 超限弃牌 | 修仙路上的取舍 |

**如果此屏幕做得不好会怎样**：玩家在信息不透明时做出后悔的购买/删除（挫败感）、看不懂自己的卡组构成（构筑策略失效）、超限弃牌感觉被系统欺骗（信任崩塌）。GDD 设计理念明确：超限弃牌不是惩罚——UI 必须让玩家在知情情况下做取舍。

**范围界定**（GDD 边界澄清 2026-09-05）：战利品三选一面板归 combat-ui（其「战利品选择网格」模式已入库）——本规范不覆盖。本规范覆盖：坊市（购买/散功/出售三标签页）、卡组浏览、超限弃牌、卡牌详情浮窗。

**来源**：deck-editing-ui-system.md「玩家幻想」表 + deck-editing-system.md §设计理念 + 用户批准。

## Player Context on Arrival

三个入口的玩家状态截然不同，UI 的信息密度与节奏须分别匹配：

| 入口 | 首次遇到时机 | 到达前刚做的事 | 情绪状态 | 自愿性 |
|---|---|---|---|---|
| **坊市（三标签页）** | 第一次到达商店节点（探索前中期） | 刚在探索节点图点击商店节点确认「进入商店」 | 平静盘算——手里有灵石，心里有构筑方向，愿意精打细算 | 自愿 |
| **卡组浏览** | 开局后任意时刻（第一次通常是战后好奇查看） | 战后/探索中/坊市中点击卡组图标 | 低压力浏览——无决策压力，只想看清全貌或回味某张卡 | 自愿 |
| **超限弃牌** | 第一次事件奖励爆卡（探索中期） | 刚看完「你获得了以下卡牌」弹窗（不可跳过）——知道了自己拿多了 | 紧张取舍——刚到手的卡要放弃一部分，患得患失 | **被迫**（游戏强制送入） |

**设计含义**：
- 坊市可承载高信息密度（价格/稀有度/卡组余量并排）——玩家有心理预算慢慢看
- 卡组浏览须**快速打开**（≤0.3s，UX AC 先例）——定位是「随手翻牌本」而非工作台
- 超限弃牌必须**信息透明优先于速度**——先展示获得物（GDD 流程 ①）再弹弃牌界面，补偿（5 灵石/张）明示——「放弃的功法回归天地」

**来源**：deck-editing-ui-system.md「玩家幻想」+ deck-editing-system.md §4 事件超限处理流程 + 用户批准（三入口分别描述）。

## Navigation Position

此屏幕组位于：**游戏主场景（探索）→ 坊市 overlay → 卡组浏览 overlay**（最深三层堆叠）。

三个界面的层级与形态不同：

| 界面 | 层级 | 形态 |
|---|---|---|
| **坊市（买卡/散功/售卡）** | 探索主场景之上 | UI overlay（2026-09-08 exploration-ui B9 裁决——非场景切换，节点图冻结；ADR-0005 的 SHOP 场景枚举不用于此入口） |
| **卡组浏览** | 全局 | UI overlay——可从探索（HUD 卡组图标）、坊市（三标签页内入口）、战利品面板（选前查看）叠加打开 |
| **超限弃牌** | 事件面板之上 | 强制模态弹窗（不可关闭返回，直到弃牌完成） |

**多入口到达**：卡组浏览是唯一从多处可达的界面（4 个入口：探索/坊市/战利品/战斗——战斗中显示完整卡组+「已抽出/仍在牌库」标注，GDD deck-editing-system §5）。坊市仅从探索商店节点进入。

**来源**：B9 裁决沿用 + deck-editing-system.md §5 查看场景表 + 用户批准。

## Entry & Exit Points

### 进入点

| 进入来源 | 触发器 | 玩家携带的上下文 |
|---|---|---|
| 探索节点图（商店节点） | 节点弹窗「进入商店」确认（exploration-ui 006 overlay 容器） | 当前灵石余额、卡组张数、境界上限 |
| HUD 卡组图标 | 探索中点击卡组图标 | 卡组数据快照 |
| 坊市内部 | 三标签页内「查看卡组」入口 | 当前坊市操作上下文（买卡决策参考） |
| 战利品面板（combat-ui） | 三选一选择前点击「查看卡组」 | 候选卡牌上下文（判断「这张进不进构筑」） |
| 事件结算（超限触发） | 事件获得卡牌后卡组 > 境界上限 → 先「你获得了以下卡牌」弹窗 → 强制进入超限弃牌 | 新获得的卡牌列表、超限张数 |
| 战斗中（卡组图标） | 战斗 HUD 点击卡组图标 | 完整卡组 + 牌库/已抽出标注 |

### 退出点

| 退出目的地 | 触发器 | 备注 |
|---|---|---|
| 探索节点图 | 坊市「离开」按钮 | 恢复节点图交互（overlay 关闭即解冻） |
| 探索节点图 | 商店节点交互完成（离开商店节点） | 同上 |
| 返回来源界面 | 卡组浏览「关闭」 | 回到打开它的那一层（探索/坊市/战利品）——非固定目标 |
| 事件面板（继续事件流程） | 超限弃牌「确认弃牌」 | **不可逆**：被弃卡牌永久移除（含 5 灵石/张补偿）——确认按钮是唯一出口，无「取消返回」 |
| 坊市三标签页切换 | 标签页点击 | 界面内导航（非退出） |

**不可逆退出警示**：超限弃牌是本屏幕组唯一不可逆操作——弹窗设计必须让玩家在确认前看清选择（已选清单+补偿金额）。

### GDD 待解决问题裁决（2026-09-08）

| GDD # | 问题 | 裁决 | 理由 |
|---|---|---|---|
| #1 | 商店商品悬停预览详情 | **采纳**——商品卡悬停弹出卡牌详情浮窗（复用模式库-悬停提示+卡牌详情浮窗），点击仍走购买确认 | 购买决策需要完整卡牌信息；GDD 界面规则已写「鼠标悬停显示完整卡牌详情」于战利品，商店对齐 |
| #2 | 超限弃牌可否「出售」替代 | **不提供**——超限弃牌界面不设出售跳转 | 保持取舍的重量感（GDD 设计理念「不是惩罚而是取舍」——提供出售逃生门会稀释决策）；出售是坊市的功能，场景不同 |
| #3 | 战利品跳过按钮默认禁用 | 不在本规范范围（战利品面板归 combat-ui） | 边界澄清 2026-09-05 |

**来源**：GDD 用户界面需求表 + deck-editing-system §4/§5 + 用户批准。

## Layout Specification

### Information Hierarchy

四个界面的信息优先级（1 = 玩家首先看到）：

**坊市（买卡/散功/售卡三标签页共用框架）：**

| 优先级 | 信息 | 为什么 |
|---|---|---|
| 1 | 灵石余额 | 所有坊市决策的硬约束——买不起/删不起一眼判断 |
| 2 | 商品/卡牌网格 | 决策主体——每张卡的信息完整自持（名称/稀有度色条/类型/费用/价格） |
| 3 | 卡组余量（28/30） | 买的约束（满了不能买）与删的动机（满了才想删） |
| 4 | 价格（嵌入每张卡） | 决策变量，随卡走不分离 |
| 5 | 标签页（买卡/散功/售卡） | 模式切换——首次进入默认「买卡」 |
| 6 | 刷新商店按钮+费用 | 低频操作 |
| 7 | 离开按钮 | 明确但非首要（右上角固定） |
| 8 | 散功当前费用（第 N 次） | 仅散功标签页——递增费用前置显示防误操作 |

**卡组浏览（只读）：**

| 优先级 | 信息 |
|---|---|
| 1 | 卡牌网格（分组/筛选/排序后） |
| 2 | 总张数统计（35/40）+ 暗金计数（1/2） |
| 3 | 筛选/排序工具栏 |
| 4 | 「历史」标签入口 |
| 5 | 关闭按钮 |

**超限弃牌：**

| 优先级 | 信息 |
|---|---|
| 1 | 需弃张数（还需选 2 张）+ 已选计数 |
| 2 | 卡组网格（可多选） |
| 3 | 灵石补偿（每弃 1 张 +5 灵石） |
| 4 | 确认按钮（选满后激活） |

**卡牌详情浮窗：** 卡名>稀有度/类型/费用>效果全文>本命加成>来源——GDD §7 已定序。

**来源**：GDD 界面规则逐条提取 + 用户批准。

### Layout Zones

三界面共享「顶部状态条 + 中央网格 + 底部操作条」三段式骨架（与商店 overlay 容器形态一致，降低学习成本）：

**坊市（1920×1080 基准，overlay 占全屏）：**

| 区域 | 尺寸 | 内容 | 依据 |
|---|---|---|---|
| 顶部状态条 | 1920×~80px | 灵石余额（左）·「🏪 坊市」标题+三标签页（中）·卡组余量+离开按钮（右） | 层级 1/3/5/7 常驻可见 |
| 中央商品网格 | ~1920×~800px | 商品卡片网格（4 列默认，3~6 列调优）——每卡：缩略图/卡名/稀有度色条/类型标签/价格 | 层级 2+4 |
| 底部操作条 | 1920×~120px | 刷新商店按钮+费用（买卡页）/散功费用+确认（散功页）/已选总价+确认出售（售卡页） | 层级 6/8——随标签页切换内容 |

**卡组浏览（overlay，中央面板 ~1400×900）：**

| 区域 | 尺寸 | 内容 |
|---|---|---|
| 顶部统计条 | ~1400×~70px | 「📋 卡组 35/40」+ 暗金 1/2 +「全部/历史」二级标签 + 关闭 |
| 工具栏 | ~1400×~50px | 筛选标签行（全部/角色/功法/法宝/阵法/丹药/符箓）+ 排序（费用/稀有度/类型/获得顺序） |
| 中央卡组网格 | ~1400×~700px | 卡牌网格（类型分组展示）+ 筛选结果为 0 时空态提示 |
| （无底部条） | — | 只读界面——无操作条 |

**超限弃牌（中央模态 ~1200×800，红色警示样式）：**

| 区域 | 尺寸 | 内容 |
|---|---|---|
| 警示头部 | ~1200×~100px | 「⚠ 卡组超限！」+ 当前 X/上限张（超限 N 张）+ 请选择 N 张弃掉 |
| 进度指示 | ~1200×~60px | 已选：X 张（还需选 Y 张）+ 补偿预览（+Z 灵石） |
| 中央卡组网格 | ~1200×~540px | 可多选卡牌网格（✓标记） |
| 确认底条 | ~1200×~100px | 「确认弃牌 ✓（获得 Z 灵石）」——选满 N 张后激活 |

**来源**：方案 A（三段式统一）用户批准 + GDD 布局线框 + exploration-ui 006 overlay 容器协作。

## Events Fired

**信号归属原则**（沿用 exploration-ui B6 裁决先例 + ADR-0007）：UI 信号为**意图/通知**；所有持久变更（灵石扣除、卡组增删、日志写入）由卡组编辑系统/资源系统在系统侧执行。UI 绝不直接操作灵石或卡组数据。

| 玩家动作 | 触发的事件 | 载荷 / 数据 |
|---|---|---|
| 购买确认 | `shop_purchase_confirmed`（意图） | `{card_id, price}` — 系统验证扣费+加卡+记日志 |
| 散功确认（二次确认后） | `deck_remove_confirmed`（意图） | `{card_id, cost}` — 系统扣费+移除+记日志 |
| 出售确认（二次确认后） | `deck_sell_confirmed`（意图） | `{card_ids: [...], total_price}` — 系统移除+入账+记日志 |
| 刷新商店 | `shop_refresh_requested`（意图） | `{cost}` — 系统扣费+重生成商品 |
| 离开商店 | `shop_exited`（通知） | `{purchases_count}` |
| 标签页切换 | `shop_tab_changed`（分析，可选） | `{tab: buy/remove/sell}` |
| 卡组浏览打开/关闭 | `deck_view_opened` / `deck_view_closed`（分析，可选） | `{source: exploration/shop/loot/combat}` |
| 筛选/排序变更 | `deck_filter_changed`（分析，可选） | `{filter, sort}` — 瞬态交互状态，UI 本地 |
| 卡牌详情查看 | `card_detail_viewed`（分析，可选） | `{card_id}` |
| 超限弃牌确认 | `overlimit_discard_confirmed`（意图） | `{card_ids: [...], compensation}` — 系统移除+补偿入账+记日志 |
| 商品悬停预览 | 无事件 | 纯视图操作 |

**标记持久游戏状态的动作**（架构团队特别关注——全部由系统侧执行）：
- `shop_purchase_confirmed` / `deck_remove_confirmed` / `deck_sell_confirmed` — 灵石+卡组变更
- `shop_refresh_requested` — 灵石扣除
- `overlimit_discard_confirmed` — 卡组变更+补偿灵石
- 每次卡组变更同时写入 DeckChangeLog（持久化——卡组浏览「历史」标签数据源，GDD §8）

**无事件动作**：商品悬停、卡牌悬停预览、弹窗内导航。

**来源**：GDD 与其他系统的交互表 + B6 裁决先例 + 用户批准。

## Data Requirements

**零状态所有权**（ADR-0031）：全部数据从系统读取；写操作仅通过意图信号（见 Events Fired）。UI 零数值计算——散功费用、出售价、补偿金额全部由系统返回后显示。

| 暗金卡计数（1/2） | 卡组编辑系统 | 读 | 统计条 |
| 散功当前费用+已删次数 | 卡组编辑系统（公式 2：50+25×次数） | 读 | UI 不计算递增——系统返回当前值 |

## Accessibility

目标等级：**WCAG-AA（基础级 + 关键标准增强）**（`design/accessibility-requirements.md` 承诺）。

| 要求 | 本屏幕的实现 |
|---|---|
| **纯键盘全路径** | 坊市（标签页 Tab/←→→ 网格方向键→底部 Tab）、卡组浏览、超限弃牌全部可无鼠标操作——焦点顺序：顶部状态条→网格（行优先）→底部操作条；Enter=确认、Esc=逐层关闭 |
| **焦点指示器** | 模式库-焦点环（松石青 2px 外部光环）——网格中焦点卡额外放大 1.05× 双编码 |
| **非颜色传达** | 灰态商品**双编码**：颜色变灰 + 「灵石不足」/「卡组已满」/「已售 ❌」文字标记；稀有度色条 + 文字标签（白色/蓝色/紫色/金色/暗金）；超限弃牌已选 = ✓标记 + 边框高亮（非仅颜色） |
| **减少动态** | 全部动画有瞬时替代（见 Transitions & Animations 晕动症防护节） |
| **文本对比度** | 卡牌文字/价格/费用文字对比度 ≥4.5:1（WCAG-AA 正文标准）；灰态文字仍需可读（≥3:1 大文本标准） |
| **卡牌替代文本** | 卡牌详情浮窗为纯文本可读结构（卡名/稀有度/类型/费用/效果全文）——屏幕阅读器可顺序朗读；商品卡的名称+价格有可聚焦文本节点 |
| **确认弹窗焦点** | 二次确认弹窗打开时焦点自动落于「取消」（安全默认——模式库-确认对话框先例） |
| **手柄可达** | A/B/LB/RB/方向键全覆盖（见 Interaction Map 手柄列）——无鼠标级精确度要求（网格吸附导航） |

**来源**：accessibility-requirements.md（WCAG-AA）+ 模式库焦点环/确认对话框先例 + 用户批准。

## Localization Considerations

源语言：中文。若未来翻译（英/日/韩），中文→拉丁语系常见膨胀约 30-40%——以下元素按膨胀 40% 不破版约束设计：

| 元素 | 最大字符预算（中文） | 膨胀风险 | 约束 |
|---|---|---|---|
| 卡牌名称 | 12 字（商品卡/网格卡单行） | **高** | 卡名区预留 40% 宽度余量；超长卡名两行截断+详情浮窗全文 |
| 按钮标签 | 6 字（「确认散功 ✓」「离开」） | **高** | 按钮宽度按最长标签+40% 设计，禁止固定像素宽 |
| 确认弹窗按钮行 | 「确认购买 [卡名]（[价格]灵石）？」整句 | **高** | 弹窗宽度自适应文案，按钮行允许换行 |
| 筛选标签 | 4 字（「法宝」「阵法」） | 中 | 标签行横向滚动兜底 |
| 历史条目 | 40 字/条 | 中 | 条目区固定高度+截断+悬停全文 |
| 稀有度文字 | 2 字（「暗金」） | 低 | 色条+文字双编码本就冗余 |
| 数字/灵石 | 灵石可至 5 位数 | 低 | 数字右对齐+千分位 |

**区域格式**：灵石数字千分位分隔（12,500）；无日期显示（历史条目用回合数非时间戳——GDD §8 字段 turn）。

**来源**：UX 规范本地化检查清单 + GDD DeckChangeLog 字段 + 用户批准。

## Acceptance Criteria

- [ ] 坊市 overlay 从商店节点确认到商品网格可交互 ≤0.5s（含展开动画）
- [ ] 卡组浏览从任意入口（HUD 图标/坊市/战利品）打开 ≤0.3s，关闭返回来源界面
- [ ] 坊市三标签页（买卡/散功/售卡）切换 ≤0.2s，底部操作条内容随标签页正确切换
- [ ] 商品悬停 0.3s 内弹出卡牌详情浮窗（GDD #1 裁决——名称/稀有度/类型/费用/效果全文）
- [ ] 价格 > 灵石的商品灰色 + 「灵石不足」文字标记（双编码，非仅颜色）；点击抖动+toast
- [ ] 卡组 ≥ 境界上限时商品卡灰色+「卡组已满」；灵石/消耗品类不受限（战利品侧先例——坊市内商品全为卡牌时全灰+空态提示）
- [ ] 购买确认后：灵石扣减数字滚动 + 卡牌飞向卡组图标（0.3s）+ 商品标记已售 + 卡组计数 +1
- [ ] 散功费用显示当前值：「散功费用：50灵石（第1次）」→ 删 1 次后显示「75灵石（第2次）」——数值与系统返回一致（UI 未计算）
- [ ] 散功/售卡时卡组仅剩 5 张：确认按钮禁用 + 「卡组至少保留5张」提示
- [ ] 出售多选：已选 N 张总价实时累计（34灵石）；二次确认含「出售后不可恢复」
- [ ] 卡组浏览筛选结果为 0 显示「没有符合条件的卡牌」空态；类型分组+排序正确
- [ ] 「历史」标签展示变更日志（回合/来源渠道/卡名/操作），读档后完整恢复（持久化验证）
- [ ] 超限弃牌：先「你获得了以下卡牌」弹窗（不可跳过）→ 弃牌界面；选满 N 张后确认按钮才激活；确认是唯一出口（无取消路径）；补偿金额（N×5灵石）实时显示
- [ ] 纯键盘可完成完整坊市流程（浏览→购买→散功→出售→离开）与超限弃牌——焦点环全程可见
- [ ] 手柄可完成坊市购买与离开（A/B/LB/RB/方向键）
- [ ] 「减少动态」开启：商品依次出现/碎裂/熔炼动画全部瞬时替代，数字直接显示终值
- [ ] 所有确认弹窗（购买/散功/出售/超限）打开时焦点自动落于「取消」侧安全默认
- [ ] 坊市 overlay 打开期间探索节点图输入冻结（缩放/平移/点击无效）；离开即解冻
- [ ] 1280×720 下限分辨率：坊市全屏 overlay/卡组浏览/超限弃牌三界面全部元素可见且不溢出（商品网格列数与筛选标签行自适应收缩；面板尺寸为 1080p 基准值，720p 按比例缩放）（2026-09-08 A4 修复——对齐 exploration-ui/combat-ui 720p 先例）
- [ ] 卡组浏览为只读界面：无任何出售/拆解/移除操作入口（2026-09-08 B1 裁决——批量出售归坊市售卡标签页；「拆解」术语不作为玩家操作）

**覆盖检查**：性能 2（坊市/卡组浏览打开时间）、导航 4（关闭返回/标签页/入口/冻结解冻）、错误空态 5（灵石不足/卡组满/5 张保护/筛选空/历史空）、无障碍 3（键盘/手柄/减少动态/焦点默认）、核心目的 4（购买/散功/出售/超限弃牌流程完整性）、分辨率 1（720p 下限）、范围界定 1（卡组浏览只读防回归）。

**来源**：GDD 验收标准 13 条 + deck-editing-system 验收标准（坊市/超限/历史部分）+ 用户批准（18 条）+ ux-review 修复（B1/A3/A4——2026-09-08 补 2 条至 20 条）。

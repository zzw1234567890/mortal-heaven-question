## HUD Philosophy

> **HUD 是修仙之路的仪表盘——一眼知全局，凝视见细节。**

「仙途问道」的 HUD 遵循**自适应密度**策略。它不是一块静态的信息牌，而是一层随着游戏状态呼吸的感知膜：

- **探索中**：极简。境界、灵石、行动力——三要素。玩家沉浸在节点地图的世界里，HUD 退为背景。
- **战斗中**：信息密集。费用、手牌、牌库、回合、敌方境界标记——决策所需的一切主动呈现。
- **商店/事件中**：介于两者之间。保留核心状态，收起战斗专属信息。

HUD 从不喧宾夺主——它在玩家需要时提供信息，在玩家沉浸时退为背景。

色彩的每一次出现都有信息载荷：朱砂红=生命在流逝，松石青=灵力在运转，琉璃金=稀有或突破。没有纯粹的装饰色。HUD 元素在统一的墨色几何框架中运作，与美术圣经的「墨骨丹青」形成一条连续的视觉纪律——从卡牌到角色到界面，规则一致。

**设计约束**（由此理念推导）：
1. 任何新增的 HUD 元素必须证明其信息载荷——不能仅为"好看"而存在
2. 色彩编码必须一致：同一种颜色在不同场景中编码同一类信息
3. 所有 HUD 元素遵守 1920×1080 基准的排版层级和图标网格（美术圣经 §7.2–7.4）

## Layout Zones

HUD 采用**全局框架 + 场景扩展**的空间组织模式。所有场景共享顶栏左右两个锚点区域（境界修为、灵石），探索和战斗分别附加右下信息面板。战斗场景额外占据屏幕中央和底部作为主内容区。

### 全局框架（所有场景共享）

```
┌──────────────────────────────────────────────────────────┐
│ [境界+修为条]                        [灵石] [卡组*]     │
│                                                          │
│                ← 中央主内容区 →                           │
│                                                          │
│ [暂停按钮]                                               │
└──────────────────────────────────────────────────────────┘
```

| 区域 | 位置 | 锚点 | 尺寸 | 内容 |
|------|:--:|------|------|------|
| **境界修为区** | 左上 | left: 16px, top: 12px | 240×56px | 境界名称 + 修为进度条 |
| **资源计数区** | 右上 | right: 16px, top: 12px | 自适应 | 灵石图标+数字（始终）；卡组图标+数量（上下文相关） |
| **暂停入口** | 左下 | left: 16px, bottom: 12px | 40×40px | 暂停/菜单图标按钮 |
| **通知区** | 中央顶部 | center-x, top: 72px | 400×120px（堆叠上限） | 通知堆叠，逐条出现/消失 |

`*` 卡组数量显示条件：探索中、商店中。战斗中隐藏（战斗有独立牌库计数）。

### 场景扩展：探索 HUD（右下）

```
┌─────────────────────────┐
│ 🏁 青云剑宗              │  ← 地图名
│ AP ████░░ 3/5           │  ← 行动力条 + 数值
│ 📍 层 3/5               │  ← 当前层/总层数
└─────────────────────────┘
```

锚点：right: 16px, bottom: 16px。尺寸：180×76px。在窗口右下角叠加于全局框架之上。

### 场景扩展：战斗 HUD（全屏叠加）

战斗 HUD 替换探索 HUD 面板，并在屏幕中央扩展为完整的战场界面。布局遵照美术圣经 §7.5.1 的战斗 HUD ASCII 线框：

```
┌──────────────────────────────────────────────────────────┐
│ [境界+修为条]              [阵法区]          [灵石]      │
├──────────────────────────────────────────────────────────┤
│                                                          │
│             敌方角色区（前/后两行排列）                     │
│                                                          │
│             己方角色区（前/后两行排列）                     │
│                                                          │
├──────────────────────────────────────────────────────────┤
│ [回合阶段指示器]                  [费用] [牌库] [回合]    │
├──────────────────────────────────────────────────────────┤
│             手牌区（底部弧形排列，7-10 张）                 │
├──────────────────────────────────────────────────────────┤
│ [结束回合]  费用: ◈◈◈◈◈ 5/8   牌库: 18   弃牌: 6         │
└──────────────────────────────────────────────────────────┘
```

| 区域 | 位置 | 内容 |
|------|:--:|------|
| **回合阶段指示器** | 顶部栏居中 | 当前阶段名 + 进度指示 |
| **敌方角色区** | 屏幕中上 | 敌方前后两排角色头像 + HP条 + 境界标识 |
| **己方角色区** | 屏幕中下 | 己方前后两排角色头像 + HP条 + 绑定卡图标 |
| **阵法区** | 顶部栏右侧 | 已部署的阵法名称 + 图标（最多 3 个） |
| **费用栏** | 底部栏左侧 | 当前费用/上限 + 临时费用显示 |
| **手牌区** | 屏幕底部 | 弧形排列 7-10 张卡牌，卡宽 100px |
| **战斗日志** | 右上折叠按钮 | 点击展开滚动文本日志 |

### 场景切换过渡

| 从 | 到 | 过渡效果 | 时长 |
|------|------|------|:--:|
| 全局 | 探索 | 右下信息面板从右侧滑入，地图名淡入 | 0.3s |
| 探索 | 战斗 | 全屏过渡提示"进入战斗"，全局框架保持，右下替换为战斗面板 | 1.0s |
| 战斗 | 探索 | 战斗面板淡出，右下恢复探索面板 | 0.3s |
| 全局 | 商店/事件 | 全局框架半透明（opacity 0.4），弹窗面板居中弹出 | 0.3s |
| 全局 | 暂停 | 全局框架保持，背景覆盖半透明黑色遮罩，暂停菜单居中弹出 | 0.3s |

## HUD Elements

### 元素 1：境界修为指示器

| 属性 | 值 |
|------|------|
| **类别** | 始终可见 |
| **位置** | 左上角，left: 16px, top: 12px，尺寸 240×56px |
| **来源 GDD** | `hud-system.md` §2 |
| **来源美术圣经** | §7.4.4 进度条、§7.2.2 字号层级 |

**显示内容**：
- 境界名称（H3, 22px 浓墨）+ 修为进度条
- 进度条颜色阈值：<50% 蓝色 → 50~90% 紫色 → ≥90% 金色脉动（1.0s 周期）
- 鼠标悬停：浮层显示具体数值（"修为 1800/2250"），16px 中墨
- 战斗中敌方境界高于玩家：境界名旁显示 `⬆` 图标 + 敌方境界标签
- "炼气·落难"状态：进度条破碎光效替代脉动
- 化神期满：显示"可飞升"标签替代进度条

**视觉形式**：H3 文本标签 + 2px 淡墨线框进度条，填充色按阈值切换
**更新行为**：事件驱动，订阅游戏状态管理器的 `cultivation_changed` 信号
**动画行为**：
- 修为增长：进度条 0.4s ease-out 平滑填充
- 修为满值：金色脉动光效，1.0s 呼吸周期
- 境界突破：名称 scale 1.2× + 松石青光效，0.8s

## Dynamic Behaviors

HUD 密度随游戏状态自适应变化——这是"自适应密度"理念的实现层。以下定义所有触发→响应规则。

### 场景切换时的密度变化

| 触发 | 进/出 | HUD 变化 | 时长 |
|------|:--:|------|:--:|
| 进入探索 | 进 | 右下行动力面板从右侧滑入；右上卡组计数显现 | 0.3s |
| 离开探索 | 出 | 右下面板向右滑出；右上卡组计数隐藏 | 0.3s |
| 进入战斗 | 进 | 右下替换为战斗面板；中央角色区+手牌区+阵法区+阶段指示器展开 | 0.5s |
| 离开战斗 | 出 | 战斗面板+角色区+手牌区+阵法区+阶段指示器淡出；右下恢复探索面板 | 0.3s |
| 打开商店/事件 | 进 | 全局框架 opacity → 0.4；弹窗居中弹出 | 0.3s |
| 关闭商店/事件 | 出 | 弹窗关闭；全局框架 opacity → 1.0 | 0.2s |
| 打开暂停 | 进 | 黑色半透明遮罩覆盖 60% alpha；暂停菜单居中弹出；所有游戏计时冻结 | 0.3s |
| 关闭暂停 | 出 | 遮罩+菜单淡出；游戏计时恢复 | 0.2s |

### 环境变化（无需玩家操作）

| 条件 | HUD 变化 | 时长/周期 |
|------|------|:--:|
| 修为 <50% | 进度条填充色：蓝色 | 0.4s 过渡 |
| 修为 50–90% | 进度条填充色：紫色 | 0.4s 过渡 |
| 修为 ≥90% | 进度条填充色：金色 + 脉动光效 | 1.0s 呼吸周期 |
| 修为满值 | "可突破！"标签 + 金色脉动 | 持续 |
| HP <20% | HP 条朱砂红闪烁 | 0.5s 周期 |
| HP=0（阵亡） | HP 条灰色 + "阵亡"标签 | 立即 |
| 卡组 = 上限 | 数字变黄色 | 立即 |
| 卡组 > 上限 | 数字朱砂红闪烁 + "超限！"标签 | 0.3s 周期 |
| 行动力 <2 | 行动力条朱砂红闪烁 | 0.5s 周期 |
| 费用 < 最低手牌费用 | 费用数字变灰 40% opacity | 立即 |
| 牌库归零 | "空牌库"淡墨标注 | 立即 |
| 无阵法部署 | 阵法区隐藏 | 立即 |

### 玩家操作触发的可用性变化

| 条件 | 视觉响应 |
|------|------|
| 手牌中费用不足的卡 | 降低至 40% 透明度 + 费用图标变灰 + 不可拖拽 |
| 卡组满时战利品卡牌选项 | 灰色 + "卡组已满"标记 + 不可选择 |
| 已通关地图重入确认 | 弹出确认窗口——显示"重入费用" + 当前灵石余额 |
| 未解锁地图 | 灰色 + 🔒 图标 + 不可点击 + 悬停显示"需 X 境界" |
| 已阵亡角色 | HP 条灰色 + "不可上场"标签 |

## Platform & Input Variants

目标平台为 PC（Steam），主要输入为键盘/鼠标。MVP 阶段无触屏、无完整手柄支持。

### 键盘/鼠标（主要）

所有 HUD 交互以鼠标为默认：悬停查看详情、点击触发、拖拽出牌。键盘快捷键为补充：

| 快捷键 | 功能 | 可用场景 |
|------|------|------|
| `ESC` | 打开/关闭暂停菜单 | 所有场景 |
| `Tab` | 切换键盘焦点至下一交互元素 | 菜单/弹窗中 |
| `1–7` | 选择手牌（战斗） | 战斗——出牌阶段 |
| `Space` | 结束回合（战斗） | 战斗 |
| `Enter` | 确认当前弹窗选项 | 弹窗中 |
| `M` | 打开/关闭地图（探索） | 探索 |
| `D` | 打开卡组查看 | 探索/商店 |
| `滚轮` | 手牌区左右滚动（手牌 >7 张时） | 战斗 |
| `滚轮` | 战斗日志面板上下滚动 | 战斗——日志展开时 |

### 手柄支持（部分，非 MVP）

手柄提供基础功能覆盖——导航和确认操作，无卡牌拖拽优化。手柄导航遵循美术圣经 §7.4.1 的焦点环规范（松石青 2px 外部光环）：

| 手柄按键 | 功能 |
|------|------|
| A / × | 确认选择 / 打出卡牌 |
| B / ○ | 取消 / 返回 |
| Start | 暂停菜单 |
| 方向键 / 左摇杆 | 导航焦点 |
| LB / RB | 手牌区翻页（>7 张时） |
| Y / △ | 查看卡牌详情（选中卡牌后） |

手柄模式下，手牌选择替代拖拽：焦点落在一张卡上 → A 键选中 → 方向键选择目标区域 → A 键确认打出。

### Steam 覆盖层兼容

所有 HUD 快捷键不与 Steam 默认覆盖层（`Shift+Tab`）冲突。ESC 键在 Steam 覆盖层打开时不响应——由 Steam Input API 处理优先级。

## Accessibility

> **无障碍等级尚未定义**——考虑将 WCAG-AA 作为基线。运行 `/gate-check` 查看是否阻塞任何阶段关口。

### 当前规范中的无障碍设计

| 检查项 | 状态 | 说明 |
|------|:--:|------|
| **纯键盘导航路径** | ✅ 已覆盖 | ESC/Tab/1–7/Space/Enter/M/D + 手柄方向键导航提供完整键盘路径 |
| **手柄导航顺序** | ✅ 已覆盖 | 焦点在逻辑区域间顺次移动：全局框架 → 战斗面板 → 手牌区 → 结束回合 |
| **文本对比度** | ✅ 符合 WCAG-AA | 浓墨 #1a1a1a 在暖白 #f5f0feb 上对比度 ≥ 4.5:1（美术圣经 §7.2.2 验证） |
| **字号最小可读** | ✅ 已满足 | 最小字号 Micro 10px 仅用于版本号；所有交互文本 ≥13px |
| **独立于颜色的传达** | ✅ 已设计 | HP 条同时用长度+数字+颜色三种维度表示；费用不足同时用灰显+不可拖拽两种方式传达；卡组超限用红色闪烁+数字+文字标签三重传达 |
| **屏幕阅读器基础** | ⚠ 待定 | Godot 4.6 的 AccessKit（ADR-0003 引用）可提供基础屏幕阅读器支持。具体映射需在实现阶段由 `accessibility-specialist` 定义 |
| **减少动态选项** | ⚠ 待定 | 修为脉动、HP 闪烁、通知滑入等动画应提供"减少动态"全局开关。当前规范定义了动画但尚未定义关闭路径 |

### 无障碍缺口

1. **"减少动态"全局开关**——修为脉动（1.0s）、HP 闪烁（0.5s）、超限闪烁（0.3s）、通知滑入（0.2s）。应在设置界面提供单一开关，关闭后所有循环动画替换为静态颜色变化
2. **卡牌颜色之外的信息冗余**——稀有度烟灰五阶编码需确认色盲玩家能否区分相邻两阶（如 R2 灰 vs R3 灰）。考虑在卡面上额外标注稀有度文字标签或图标数量

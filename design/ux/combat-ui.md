## Purpose & Player Need

**核心目的**：战斗 UI 是玩家在回合制卡牌对战中的指挥台——它将战斗系统的 7 阶段状态模型、费用管理、角色上场/绑定/阵法等复杂规则转化为可理解、可操作的视觉界面，让玩家在每一回合都能做出明智的战术决策。

**玩家需求**：

1. **策略清晰度**——玩家在任何时刻都能看到当前阶段、可用费用、手牌选项、场上角色状态，无需翻阅菜单即可做出出牌/攻击/撤退决策。这是支柱 1「自由组牌，策略为王」的战斗侧落地。
2. **操作流畅度**——出牌拖拽、攻击目标选择、备战阵位调整等核心交互必须流畅且无歧义。鼠标拖拽出牌是主要路径，键盘 1-7 快捷出牌是加速路径。
3. **状态可读性**——16 个角色位（最多）的 HP/ATK/buff/debuff/境界/绑定状态需要以可扫读的方式呈现，而非逐个点击查看。
4. **反馈即时性**——每一次操作（出牌、攻击、阵法激活）都有清晰的视觉+音频反馈，玩家不需要猜测操作是否生效。
5. **幻想沉浸感**——战斗 UI 的视觉风格遵循「墨骨丹青」美术方向，让玩家感到自己在指挥一场修仙世界的对决，而非操作一个数据表格。

**完成这句话**：「玩家进入战斗时想要——在清晰的视觉框架下做出战术决策，每一步都看得见、摸得着、不后悔。」

**GDD 需求约束**（来自 `combat-ui-system.md` §用户界面需求）：
- 16 个界面区域需覆盖：备战面板、手牌区、场上角色区、费用栏、阵法区、回合阶段指示器、攻击目标选择、攻击模式指示器、战斗日志、敌方手牌区、战斗结算（胜利/战败）、撤退确认、渡劫战前 warning、悬浮详情面板、战利品三选一
- 7 阶段战斗模型（0-6：准备/抽牌/出牌/攻击声明/攻击结算/敌方行动/结束）
- Draw Call ≤200，60fps，1280×720 最低分辨率

## Player Context on Arrival

**首次遇到此屏幕的时机**：玩家在探索阶段点击战斗节点（普通/精英/Boss），确认进入后场景切换到战斗界面。第一次战斗通常在探索炼气期地图的前几层遭遇。

**到达前玩家刚在做什么**：
- 在探索 UI 的节点图上点击战斗节点 → 弹出节点确认弹窗（敌人信息+推荐战力） → 点击「进入战斗」
- 或者：在备战阶段（阶段 0）选择角色上场和阵位布局

**设计应假设的情绪状态**：
- **紧张+期待**——玩家即将进入策略对战，手中有牌但不知道敌人会怎么行动
- **决策准备态**——玩家需要在备战阶段做出角色选择和阵位决策，进入战斗后需要规划出牌顺序
- **信息饥饿→信息满足**——到达时玩家需要快速获取「我有什么牌、多少费用、敌人是谁、什么阶段」的信息

**玩家是自愿到达此屏幕还是被游戏送到这里**：
- 普通战斗/精英战斗：自愿——玩家在节点图上主动选择进入
- Boss 战：半自愿——玩家点击 Boss 节点触发，但有渡劫战前 warning 作为最后取舍机会
- 事件触发的战斗：被动——事件结果触发战斗（如「触怒NPC」类事件）

**旅程上下文缺口**：`design/player-journey.md` 不存在。设计假设基于 GDD 中的玩家幻想段落和战斗系统的 7 阶段模型推断。待解决问题中将记录此缺口。

## Navigation Position

战斗 UI 不是导航层级的顶级目的地——它是上下文相关的战斗场景内嵌界面。玩家无法从主菜单直接跳转到战斗 UI。

**此屏幕位于**：

```
[根] → [探索 UI 节点图] → [战斗节点确认弹窗] → [备战面板] → [战斗 UI]
```

**替代进入路径**：

```
[根] → [探索 UI 节点图] → [Boss 节点] → [渡劫战前 warning] → [战斗 UI]
[根] → [探索 UI 节点图] → [事件节点] → [事件结果触发战斗] → [战斗 UI]
```

**导航性质**：上下文相关——仅在战斗场景激活时可见，战斗结束后自动退出到结算面板，不作为独立屏幕持久存在。

**HUD 关系**：进入战斗场景时，全局 HUD 系统隐藏（边界澄清 2026-09-05），战斗 UI 接管所有信息显示职责（包括费用、HP、回合等，这些在探索场景中由 HUD 负责的元素在战斗中由 combat-ui 负责）。

## Entry & Exit Points

| 进入来源 | 触发器 | 玩家携带的上下文 |
|---|---|---|
| 探索 UI 节点图 | 点击战斗节点 → 确认弹窗「进入战斗」 | 当前卡组、角色列表、灵石余额、敌人信息 |
| Boss 节点 | 点击 Boss 节点 → 渡劫战前 warning → 确认 | 当前卡组、角色列表、Boss 信息、撤退代价警示 |
| 事件结果 | 事件选项触发战斗 | 当前卡组、角色列表、事件上下文（可能带 buff/debuff） |
| 备战面板 | 确认角色选择+阵位布局 → 「开始战斗」 | 已选角色列表、阵位布局、卡组（已洗牌） |

| 退出目的地 | 触发器 | 备注 |
|---|---|---|
| 战斗结算（胜利） | 所有敌方角色阵亡 → 自动触发 | 不可逆——战斗状态结束，进入战利品三选一 |
| 战斗结算（战败） | 所有己方角色阵亡 → 自动触发 | 不可逆——触发修为损失/角色损失流程 |
| 撤退 | 玩家点击撤退按钮 → 撤退确认弹窗 → 确认 | 半可逆——撤退视为战败处理（见 combat-system.md §9），修为损失 80%（渡劫战）或常规惩罚 |
| 暂停菜单 | ESC 键 / 点击暂停按钮 | 可逆——暂停冻结战斗，返回后状态不变 |

**不可逆退出**：
- 胜利结算 → 战利品选择后不可返回战斗
- 战败结算 → 确认后不可返回
- 撤退 → 确认后不可撤销

## Layout Specification

### Information Hierarchy

战斗 UI 需要传达的信息项，按玩家注意力优先级排列：

**第一层（必须立即可见——战斗决策核心）**：
1. **当前阶段名称+进度**——玩家现在能做什么（出牌？攻击？等待？）
2. **可用费用/上限**——能打几张牌
3. **手牌卡牌**——当前可用的战术选项
4. **己方场上角色**（HP/状态）——谁还活着、谁危险
5. **敌方场上角色**（HP/状态/境界）——要打谁、敌人什么状态

**第二层（战斗中持续可见——辅助决策）**：
6. **牌库剩余/弃牌堆计数**——还能抽到什么
7. **回合编号**——战斗进展到第几轮
8. **阵法区**——已部署阵法及其效果
9. **敌方境界标记**——是否有境界压制
10. **绑定功法/法宝图标**——每个角色的绑定状态

**第三层（按需可见——深度信息）**：
11. **悬浮详情面板**——悬停卡牌/角色/阵法时展开
12. **战斗日志**——默认折叠，展开查看历史行动
13. **备战面板**（仅阶段 0）——角色选择+阵位布局

**第四层（状态触发——非常驻）**：
14. **攻击目标选择标记**（阶段 3）——蓝色脉冲/红色高亮/锁定标记
15. **攻击模式指示器**（阶段 3 进入时）——短暂提示文字
16. **战利品三选一**（胜利结算后）——3 个奖励选项
17. **撤退确认弹窗**——玩家点击撤退时
18. **渡劫战前 warning**——进入渡劫战前

### Layout Zones

采用**经典对峙布局**（方案 A）——上敌下我，符合卡牌游戏视觉惯例。

**分辨率基准**：1920×1080，不支持 1280×720 以下（GDD 原始最低分辨率要求已更新为 1920×1080）。

```
┌──────────────────────────────────────────────────────────┐
│  [≡日志]    [回合阶段指示器]    [阵法区]        [⏸暂停]  │ ← 顶部条 (高度 60px)
│                                                            │
│      [敌方角色区·后排]          [敌方角色区·前排]          │ ← 敌方区 (高度 ~340px)
│      [敌方角色区·后排]          [敌方角色区·前排]          │
│                                                            │
│    ┄┄┄┄┄┄┄┄┄┄┄┄ 中线分隔 ┄┄┄┄┄┄┄┄┄┄┄┄┄┄                │
│                                                            │
│      [己方角色区·后排]          [己方角色区·前排]          │ ← 己方区 (高度 ~340px)
│      [己方角色区·后排]          [己方角色区·前排]          │
│                                                            │
│  [费用]  [手牌弧形区]           [牌库] [弃牌] [回合]       │ ← 底部条 (高度 ~180px)
└──────────────────────────────────────────────────────────┘
```

**区域定义**：

| 区域 | 位置 | 尺寸 (1920×1080) | 内容 | 引用模式 |
|------|------|-------------------|------|----------|
| 顶部条 | 顶部全宽 | 1920×60px | 日志入口、回合阶段指示器、阵法区、暂停按钮 | 回合阶段指示器（模式库）+ 图标按钮（模式库） |
| 敌方角色区 | 上半场中央 | ~1400×340px | 敌方角色卡（HP/ATK/状态/buff-debuff 图标/绑定标记/境界标记） | 新模式：角色状态卡 |
| 中线分隔 | 水平中分线 | 全宽 1px 淡墨 | 前后排视觉分界（实线/虚线 + 100%/85% 缩放区分） | — |
| 己方角色区 | 下半场中央 | ~1400×340px | 己方角色卡（同敌方+待命/已行动标记） | 新模式：角色状态卡 |
| 底部条 | 底部全宽 | 1920×180px | 费用栏、手牌弧形区、牌库/弃牌计数、回合数 | 手牌布局（模式库）+ 状态图标+计数器（模式库） |

| 备战面板 | 阶段 0 全屏覆盖 | 1920×1080 | 角色选择+阵位布局预览 | 覆盖层（模式库） |
| 攻击目标选择层 | 阶段 3 叠加 | 全屏覆盖 | 蓝色脉冲/红色高亮/箭头连线 | 新模式：攻击目标选择 |
| 战斗结算面板 | 胜利/战败触发 | 居中覆盖 | 战利品/损失摘要 | 覆盖层（模式库） |
| 撤退确认弹窗 | 玩家触发 | 居中覆盖 | 后果说明+确认/取消 | 确认对话框（模式库） |

**角色区布局细节**：
- 每方最多 6 个角色位（化神期上限），前排 3+后排 3
- 角色卡尺寸：120×168px（前排 100%缩放）/ 102×143px（后排 85%缩放）
- 前后排间距：24px
- 角色卡间距：16px
- 6 角色位总宽：3×120 + 2×16 + 24 + 3×102 + 2×16 = 360+32+24+306+32 = 754px（在 1920 宽下充足居中）

#### 新模式汇总

本规范引入以下新模式，需添加到交互模式库：
1. **角色状态卡** (Character Status Card) — 角色头像+HP/ATK/状态图标的复合显示组件
2. **阵法槽位** (Formation Slot) — 已部署阵法卡展示+空位虚线框
3. **备战阵位预览** (Deployment Preview Grid) — 拖拽调整前后排的阵位预览
4. **攻击目标选择** (Attack Target Selection) — 蓝色脉冲/红色高亮/箭头连线的目标选择层
5. **战利品选择网格** (Loot Selection Grid) — 三选一奖励选项卡片网格

- `character_deployed` / `character_undeployed` — 修改战斗状态（非持久存档，但影响战斗结果）

## Transitions & Animations

### 屏幕进入过渡

从探索 UI 进入战斗时：
1. **遮罩淡入**（0.3s）——全屏半透明黑色遮罩从 0% → 60%
2. **场景切换**——探索场景卸载，战斗场景加载（加载期间遮罩上显示「进入战斗」+⚔图标+旋转太极图加载指示器）
3. **战斗 HUD 淡入**（0.5s）——遮罩从 60% → 0%，战斗 UI 各区域从位置外滑入：
   - 顶部条从上方滑入（0.3s，ease-out）
   - 敌方角色区从上方淡入（0.4s，延迟 0.1s）
   - 己方角色区从下方淡入（0.4s，延迟 0.2s）
   - 底部条从下方滑入（0.3s，延迟 0.3s）
   - 手牌卡牌逐张从牌库位置飞入弧形位（0.15s/张，延迟 0.4s）

### 屏幕退出过渡

**胜利退出**：
1. 战斗结算面板淡入（0.3s）→ 战利品选择 → 确认后
2. 遮罩淡入（0.3s）→ 场景切换到探索 UI → 遮罩淡出

**战败退出**：
1. 战败结算面板淡入（0.3s）→ 确认后
2. 遮罩淡入（0.5s，暗色调）→ 场景切换到主菜单/探索 → 遮罩淡出

**撤退退出**：
1. 撤退确认弹窗关闭（0.15s）
2. 遮罩淡入（0.3s）→ 场景切换到探索 UI → 遮罩淡出

### 屏幕内状态转换动画

| 状态转换 | 动画 | 时长 |
|---|---|---|
| 阶段切换 | 阶段指示器文字 slide-in + 进度格逐一填充 | 200ms（文字）/ 150ms（每格） |
| 抽牌 | 卡牌从牌库位置飞入手牌弧形位 | 300ms/张 |
| 出牌 | 卡牌从手牌飞向目标区域 + 费用栏扣减动画 | 400ms |
| 攻击声明 | 箭头从攻击者延伸到目标 | 200ms |
| 攻击结算 | 受击闪白 + 伤害飘字浮起+消失 + HP条减少 | 闪白 100ms / 飘字 800ms / HP条 300ms |
| 角色阵亡 | 角色卡碎裂消散动画 | 500ms |
| 角色上场（备战） | 角色卡从列表滑入阵位 | 300ms |
| 阵法激活 | 阵法卡光芒脉冲 + 光环效果 | 400ms |
| 费用消耗 | 费用栏数字减少 + 粒子消散 | 200ms |
| 手牌重排 | 卡牌滑动到新弧形位置 | 200ms ease-out |

### 减少动态选项

以下动画应在「减少动态」全局开关启用时提供静态替代：
- 阶段指示器进度格填充 → 直接填充，无 slide-in
- 抽牌飞入 → 直接出现在弧形位，无飞行动画
- 攻击箭头延伸 → 直接显示完整箭头
- 受击闪白 → 直接显示伤害飘字
- 角色阵亡碎裂 → 直接淡出消失
- 阵法光芒脉冲 → 静态高亮
- 费用消散粒子 → 无粒子，仅数字扣减
- 手牌重排滑动 → 瞬间到位

## Accessibility

> **无障碍等级尚未正式定义**——`design/accessibility-requirements.md` 存在但未读取。`hud.md` 已建立 WCAG-AA 目标基线。本规范沿用同一基线。

### 当前规范中的无障碍设计

| 检查项 | 状态 | 说明 |
|---|:---:|---|
| **纯键盘导航路径** | ✅ 已覆盖 | Tab/Shift+Tab 在所有可交互元素间循环；数字键 1-7 快捷出牌；Enter 激活；ESC 暂停/取消 |
| **手柄导航顺序** | ✅ 已覆盖 | 方向键/左摇杆在逻辑区域间顺次移动：顶部条 → 敌方角色区 → 己方角色区 → 底部条 → 手牌区 |
| **手柄出牌路径** | ✅ 已覆盖 | 方向键选手牌 → A 键选中 → 方向键选目标 → A 键确认打出（替代拖拽） |
| **文本对比度** | ✅ 符合 WCAG-AA | 浓墨 #1a1a1a 在暖白 #f5f0eb 上对比度 ≥ 4.5:1（美术圣经 §7.2.2）；角色卡上叠加遮罩 40-60% 保证文字在头像上可读 |
| **字号最小可读** | ✅ 已满足 | 最小字号 Small 13px 用于辅助信息；HP/ATK 数字 ≥16px Data 层级 |
| **独立于颜色的传达** | ✅ 已设计 | HP 条同时用长度+数字+颜色三种维度；费用不足同时用灰显+不可拖拽两种方式；待命/已行动用图标+文字标签（非仅颜色） |
| **角色卡头像可读性** | ✅ 已设计 | 底部渐变遮罩 40-60% 确保 HP/ATK/境界文字在头像背景上可读；功法/法宝图标有半透明背板 |
| **双焦点系统（Godot 4.6）** | ⚠ 待实现 | 键盘焦点（Tab/数字键）与鼠标焦点（悬停/拖拽）分离——需显式定义焦点环视觉与鼠标悬停高亮的区分策略。焦点环：松石青 2px 外部光环；鼠标悬停：墨色边框加粗+微发光。两者同时激活时优先显示鼠标悬停态 |
| **屏幕阅读器基础** | ⚠ 待定 | Godot 4.6 AccessKit 可提供基础支持。具体映射需实现阶段由 accessibility-specialist 定义 |
| **减少动态选项** | ⚠ 待实现 | 本规范已定义减少动态替代方案（见过渡与动画 §减少动态选项），需在设置界面提供全局开关 |

### 无障碍缺口

1. **双焦点系统视觉区分**——Godot 4.6 键盘焦点和鼠标焦点分离，需要明确两者同时激活时的优先级和视觉区分。当前设计：焦点环（松石青）用于键盘/手柄；墨色边框加粗用于鼠标悬停。同时激活时显示鼠标悬停态。
2. **角色卡信息密度**——功法/法宝图标（每侧最多3个）+buff/debuff 图标（最多5个）+HP/ATK+境界标记在 120×168px 卡牌上可能信息过载。需在实现阶段测试色盲玩家和小屏用户的可读性。
3. **战斗日志无障碍**——RichTextLabel 滚动日志需确保键盘可聚焦+方向键滚动。当前设计日志默认折叠，需验证展开后的键盘导航路径。

## Localization Considerations

**此屏幕上最长的文本元素**：
- 阶段名称（7 个）：「备战」「抽牌」「出牌」「攻击声明」「攻击结算」「敌方行动」「结束」——每个 2-4 字，布局空间充裕
- 战斗日志条目格式：`[回合·阶段] 行动者 → 动作 → 目标 → 数值`——最长可能 30-40 字符，ScrollContainer 内自适应
- 撤退确认弹窗文案：「撤退将视为战败处理，损失 80% 修为。确定撤退？」——约 20 字符，对话框内自适应
- 渡劫战前 warning：「天劫在前，退路将断。确认进战？」——约 15 字符

**布局关键约束**：
- 阶段指示器进度格——7 格 + 名称，每格 80px 宽，名称 2-4 字符。英语翻译后 "Preparation" / "Draw" / "Action" / "Declare" / "Resolve" / "Enemy" / "End" 长度不等，最长 "Preparation" 11 字符可能溢出 80px 格。**高优先级**标记——需在本地化阶段测试缩短翻译或缩写。
- 费用栏数字——纯数字，无本地化问题
- 境界名称——用不同图标区分境界（非文字），鼠标悬停显示境界名。无布局溢出风险，本地化仅影响悬停 tooltip 文本。**低优先级**。
- 撤退/渡劫弹窗——对话框宽度 280-320px，中文文案无问题，英语/其他语言膨胀 40% 后可能需要 2 行。对话框应自适应高度。

**数字/货币格式**：
- 灵石数量——≥1000 显示「1.2k」格式，各语言通用
- HP/ATK 数字——纯数字，无本地化问题
- 伤害飘字——「-15」「+10」格式，需注意阿拉伯数字 vs 其他数字系统（本游戏目标语言仅中文/英文，无此问题）

**高优先级本地化元素汇总**：

| 元素 | 中文长度 | 英文膨胀风险 | 布局约束 | 优先级 |
|---|---|---|---|---|
| 阶段名称 | 2-4 字 | 高（"Preparation" 11 字符） | 80px 进度格 | 高 |
| 境界图标 | 1 图标 | 低（图标通用，tooltip 自适应） | 角色卡右下角 24px | 低 |
| 撤退/渡劫弹窗文案 | 15-20 字 | 低 | 280-320px 对话框 | 中 |
| 战斗日志条目 | 30-40 字 | 中 | ScrollContainer 自适应 | 低 |

## Acceptance Criteria

### 性能
- [ ] 战斗场景在 Godot 4.6 D3D12 渲染器下运行，帧时间 ≤16.6ms（60fps）
- [ ] 标准战斗场景（16 角色位 + 7 手牌 + 阵法区 + 阶段指示器）实测 draw call ≤200
- [ ] 从点击「进入战斗」到战斗 HUD 完全可见（含手牌飞入动画完成）≤2s

### 导航
- [ ] 从探索 UI 点击战斗节点 → 确认弹窗 → 进入战斗 → 备战面板显示，全流程 ≤2s
- [ ] 战斗胜利 → 战利品三选一面板弹出 → 选中奖励 → 确认 → 返回探索 UI，全流程可完成
- [ ] ESC 键随时打开暂停菜单，ESC 再次按下关闭暂停菜单返回战斗，战斗状态不变

### 交互
- [ ] 鼠标拖拽手牌到有效目标区域释放 → 卡牌出牌成功，费用扣减
- [ ] 鼠标拖拽手牌到无效区域释放 → 卡牌回弹到手牌弧形位，无费用扣减
- [ ] 键盘数字键 1-7 对应手牌位置，按下选中对应卡牌
- [ ] 阶段 3（攻击声明）敌方角色卡显示红色高亮可点击，点击后显示攻击箭头连线
- [ ] 手牌区 >7 张时滚轮可滚动浏览溢出卡牌

### 状态/错误
- [ ] 手牌数量为 0 时，手牌弧形区显示「无可用手牌」提示，牌库计数器高亮
- [ ] 费用不足时尝试出牌，卡牌灰显且不可拖拽，无费用扣减
- [ ] 卡组已满时战利品中的卡牌选项灰色标注「卡组已满」，不可选中

### 无障碍
- [ ] 所有可交互元素在键盘 Tab 导航下可到达，松石青焦点环可见
- [ ] 手柄方向键+A 键可完成「选手牌→选目标→出牌」全流程，无需鼠标
- [ ] HP 条同时显示长度+数字+颜色三种维度，色盲玩家可通过数字和长度读取

### 角色状态卡
- [ ] 角色头像占满卡牌背景，HP/ATK/境界文字在遮罩层上可读（对比度 ≥ 4.5:1）
- [ ] 功法图标竖排在角色卡左侧（最多 3 个），法宝图标竖排在右侧（最多 3 个）
- [ ] 前排角色卡 100% 缩放+实线边框，后排 85% 缩放+虚线边框，视觉可区分

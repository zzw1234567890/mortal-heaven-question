## Purpose & Player Need

暂停菜单是「路边的驿站」——它不需要建立世界观（玩家已经在游戏中了），它需要的是**即时可用、零学习成本、安全不丢数据**。

与主菜单（"门扉"）不同，暂停菜单的核心情感是**安心的掌控感**：玩家在任何时刻按下 ESC，世界暂停，一切冻结——「我可以安全地离开、调整、或回来，一切如常」。

**核心玩家需求**：
1. **暂停与继续** —— 一键暂停，一键回来。暂停不是退出——玩家大多数时候按暂停只是去倒杯水。「继续游戏」必须是最显眼、最快速的选择
2. **安全退出** —— "保存并退出"和"返回主菜单"必须清楚区分。"保存"意味着可以回来——"返回"意味着可能丢进度，需要确认
3. **战斗中查看信息** —— 战斗中暂停时，玩家需要查看卡组了解当前构筑，但不能编辑（公平性）。「查看卡组」按钮进入只读模式
4. **调整系统设置** —— 玩到一半发现声音太大/太小，快速进入设置调整后无缝返回游戏

如果暂停菜单做得不好：玩家在倒水前犹豫「我的进度会丢吗」，或误点「返回主菜单」丢失进度后愤怒。

## Player Context on Arrival

玩家在三种截然不同的游戏状态下按 ESC 到达暂停菜单，每种状态要求不同的信息呈现：

**场景 1：探索中暂停（平静打断）**
玩家正在规划路线、浏览节点、决定去哪张地图。暂停是自然的中断——倒水、吃饭、接电话。情绪状态：平静、无时间压力。回来后他们需要快速恢复空间感知——「我刚才在哪儿？我在哪张地图？第几层？」——暂停菜单上的探索进度信息为此服务。

**场景 2：战斗中暂停（紧张打断）**
玩家正在关键回合中思考出牌策略——或者被现实打断（有人敲门）。情绪状态：紧张、注意力集中、可能需要时间思考。战斗暂停时不允许编辑卡组（公平性——不能让玩家在暂停中无限制分析），但允许查看卡组（信息透明——「我的牌库里还有什么？」）。回合计时冻结。

**场景 3：商店/事件中暂停（间歇打断）**
玩家正在做消费/选择决策——或刚结束决策还没点确定。暂停后回来需要看到他们正在做的选择还在原位。

**共通原则**：暂停后回来的玩家（尤其是场景 1/2 的打断后）需要 **2 秒内恢复情境感知**。暂停菜单关闭时不应改变任何游戏状态——他们离开时的世界和回来时完全一致。

## Navigation Position

暂停菜单是**覆盖层（Overlay）**，不属于游戏的导航层级。它覆盖在所有场景之上——探索、战斗、商店、事件——无论玩家身处何处。

```
[游戏世界: 探索 / 战斗 / 商店 / 事件]
         │
         ▼  ESC / 点击暂停按钮
  ┌─────────────────────┐
  │     暂停菜单 (覆盖层)  │
  │                     │
  │  [继续游戏] ←默认焦点  │
  │  [查看卡组]          │
  │  [系统设置]          │
  │  [保存并退出]        │
  │  [返回主菜单]        │
  │                     │
  │  探索进度信息         │
  └─────────────────────┘
         │
         ▼  关闭（继续游戏 / ESC / 点击遮罩）
[回到原来的游戏世界——一切不变]
```

从暂停菜单可以进入的二级界面：
- **系统设置**（覆盖在暂停菜单之上——设置关闭后回到暂停菜单）
- **查看卡组**（覆盖在暂停菜单之上——只读模式，关闭后回到暂停菜单）

## Entry & Exit Points

### 进入点

| 进入来源 | 触发器 | 玩家携带的上下文 |
|------|------|------|
| 任意游戏场景 | 按下 `ESC` 键 | 当前场景类型（探索/战斗/商店/事件）+ 当前进度 |
| 任意游戏场景 | 点击 HUD 左下角暂停按钮 | 同上 |

### 退出点

| 退出目的地 | 触发器 | 备注 |
|------|------|------|
| **回到游戏**（原位） | 点击「继续游戏」 | 所有游戏计时恢复 |
| **回到游戏**（原位） | 按 `ESC` 键 | 等效于「继续游戏」 |
| **回到游戏**（原位） | 点击遮罩区域（菜单面板外） | 等效于「继续游戏」 |
| **系统设置**（暂留） | 点击「系统设置」 | 暂停菜单保留在背后，设置关闭后回到暂停菜单 |
| **查看卡组**（暂留） | 点击「查看卡组」 | 只读界面覆盖在暂停菜单之上，关闭后回到暂停菜单 |
| **主菜单** | 点击「保存并退出」→ 确认 | **不可逆**——保存当前进度后返回主菜单，本次游戏会话结束（但可通过"继续游戏"恢复） |
| **主菜单** | 点击「返回主菜单」→ 确认 | **不可逆**——放弃当前进度返回主菜单，未保存的进度丢失 |

**关键区分**：
- 「保存并退出」 vs 「返回主菜单」：前者存档、后者不存档。后者需要二次确认 + 明确告知「未保存的进度将丢失」。
- 战斗中无「保存并退出」——战斗不支持中退保存。战斗中只有「返回主菜单」（放弃本场战斗）= 视为战败。后续考虑是否支持「战斗暂存」。

## Layout Specification

### Information Hierarchy

暂停菜单的信息层级遵循一个原则：**最高频操作在最易达的位置，危险操作被有意阻隔**。

| 优先级 | 元素 | 理由 |
|:--:|------|------|
| 1 | 继续游戏 | 最常见操作——默认焦点，视觉最突出 |
| 2 | 保存并退出 | 安全离开路径——次常用 |
| 3 | 系统设置 | 偶尔使用——有明确目的时进入 |
| 4 | 查看卡组 | 战斗中偶尔使用——只读信息浏览 |
| 5 | 返回主菜单 | 罕见 + 危险——需要分隔 + 二次确认 |
| 6 | 探索进度文本 | 辅助上下文——底部小字，非交互 |

### Layout Zones

暂停菜单采用**居中竖直列表面板**方案——这是 Roguelike 卡牌游戏的标准暂停模式（Slay the Spire、Monster Train 均使用此方案）。它被设计为覆盖在游戏画面之上的模态层。

```
┌──────────────────────────────────────────────────┐
│  半透明黑色遮罩 (#000000, 60% alpha) + 背景模糊    │
│                                                  │
│          ┌────────────────────┐                  │
│          │     ⏸ 暂停         │  ← 标题 28px H2   │
│          │                    │                  │
│          │  [继续游戏]         │  ← 主要按钮 默认焦点 │
│          │  [查看卡组]         │  ← 次要按钮        │
│          │  [系统设置]         │  ← 次要按钮        │
│          │  ─────────────     │  ← 1px 淡墨分隔线  │
│          │  [保存并退出]       │  ← 次要按钮        │
│          │  [返回主菜单]       │  ← 危险按钮 朱砂红  │
│          │                    │                  │
│          │  探索进度：         │  ← Small 13px 淡墨 │
│          │  青云剑宗 · 层 3/5  │                  │
│          └────────────────────┘                  │
│                                                  │
└──────────────────────────────────────────────────┘
```

| 区域 | 位置 | 尺寸 | 内容 |
|------|:--:|------|------|
| **遮罩层** | 全屏 | 100%×100% | 半透明黑色 #000000 60% alpha + 背景模糊 |
| **暂停面板** | 居中 | 320×380px | 暖白基底 #f5f0eb + 1px 墨色边框 + 8px 圆角 + 24px 内边距 |
| **标题区** | 面板顶部居中 | 320×48px | ⏸ 图标 + "暂停" H2 28px 浓墨 |
| **选项列表区** | 标题下方 | 320×260px | 5 个按钮纵向排列，间距 8px |
| **进度信息区** | 面板底部 | 320×32px | 探索进度文本，Small 13px 淡墨 |

## States & Variants

暂停菜单有三种场景状态变体，按钮可用性根据不同场景调整。

| 状态 / 变体 | 触发器 | 变动的部分 |
|------|------|------|
| **默认（探索中暂停）** | ESC 或点击暂停按钮——探索场景 | 全部 5 个按钮可用。「保存并退出」可用——探索支持随时存档 |
| **战斗中暂停** | ESC 或点击暂停按钮——战斗场景 | 「保存并退出」隐藏（战斗中不可存档）。「查看卡组」进入只读模式——不可编辑卡组。进度信息显示"战斗中 · 第 N 回合"替代探索进度 |
| **商店/事件中暂停** | ESC 或点击暂停按钮——商店/事件场景 | 「保存并退出」隐藏——商店/事件为过渡场景，不独立存档。进度信息显示场景类型 + 当前上下文 |

### 保存并退出确认弹窗（所有场景）

点击「保存并退出」后弹出确认弹窗：

```
┌──────────────────────────────┐
│  保存并退出？                 │
│                              │
│  当前进度将被保存。            │
│  下次可通过「继续游戏」恢复。   │
│                              │
│  [确认保存]    [取消]         │
└──────────────────────────────┘
```

### 返回主菜单确认弹窗

点击「返回主菜单」后弹出确认弹窗：

```
┌──────────────────────────────────┐
│  ⚠ 返回主菜单？                  │
│                                  │
│  未保存的进度将丢失。              │
│                                  │
│  [保存并退出]    [不保存]   [取消] │
└──────────────────────────────────┘
```

战斗中的「返回主菜单」额外提示："当前战斗进度将丢失——视为战败。"

### 空状态

暂停菜单无数据依赖元素——所有按钮始终存在（仅按场景调节可见性）。无空状态。

### 加载状态

暂停菜单无异步加载——打开即显示。系统设置界面在暂停菜单背后打开时有短暂过渡。

### 保存失败错误状态

点击「保存并退出」→ 确认后，若 SaveLoadSystem 写入失败（磁盘满、权限不足、文件锁定）：

```
┌──────────────────────────────────────┐
│  ⚠ 保存失败                          │
│                                      │
│  磁盘空间不足或权限不足。              │
│  请检查后重试。                       │
│                                      │
│  [重试]    [不保存返回游戏]           │
└──────────────────────────────────────┘
```

- **[重试]** —— 重新尝试保存。仍然失败则再次弹出此提示
- **[不保存返回游戏]** —— 关闭暂停菜单，回到游戏（进度未保存）
- 暂停菜单保持打开——玩家不会被踢出游戏，进度不丢失

## Events Fired

| 玩家动作 | 触发的事件 | 载荷 / 数据 |
|------|------|------|
| 打开暂停菜单 | `PAUSE_MENU_OPENED` | `scene_type`（exploration/combat/shop/event） |
| 关闭暂停菜单（继续游戏） | `PAUSE_MENU_CLOSED` | `action: "resume"` |
| 进入查看卡组 | `CARD_DECK_VIEWED` | `source: "pause_menu"`, `scene_type` |
| 进入系统设置 | `SETTINGS_OPENED` | `source: "pause_menu"` |
| 保存并退出（确认后） | `GAME_SAVED` → `RETURN_TO_MAIN_MENU` | `save_slot`, `scene_type`, `progress_summary` |
| 返回主菜单（确认后） | `RETURN_TO_MAIN_MENU` | `scene_type`, `unsaved: true` |
| 确认弹窗——取消 | `CONFIRMATION_CANCELLED` | `confirm_type`（save_and_exit / return_to_menu） |

**修改持久游戏状态的动作**（需架构团队关注）：
- 「保存并退出」——触发 `GAME_SAVED` 事件，写存档文件。涉及 SaveLoadSystem（ADR-0002）——写操作需原子性保证，需返回成功/失败状态；失败时触发保存失败错误提示
- 「返回主菜单」（不存档）——不写存档，但需要清理当前游戏会话状态。战斗中放弃的完整流程：确认 → 触发 `COMBAT_RESIGNED`（视为战败）→ 显示战败结算画面（与正常战败一致）→ 玩家点击「返回」→ 回到主菜单。结算画面行为由战斗 UX 规范定义

## Data Requirements

暂停菜单本身不显示游戏数据（除了底部的探索进度文本），它是一个导航枢纽——链接到游戏内的其他界面。

| 数据 | 源系统 | 读 / 写 | 备注 |
|------|------|:--:|------|
| 当前场景类型 | 场景管理器（ADR-0005） | 读 | 决定「保存并退出」可见性和进度文本内容 |
| 探索进度（地图名+层数） | 探索系统 | 读 | 仅探索中显示——帮助玩家恢复空间感知 |
| 战斗回合数 | 战斗系统（ADR-0008） | 读 | 仅战斗中显示——"战斗中 · 第 N 回合" |
| 存档操作 | 存档加载系统（ADR-0002） | 写 | 仅「保存并退出」时触发原子写入。需返回成功/失败状态——失败时触发错误提示 |
| 卡组数据 | 卡牌系统（ADR-0006） | 读 | 「查看卡组」只读访问 |

## Acceptance Criteria

- [ ] 任意游戏场景按 ESC 或点击 HUD 暂停按钮，0.25s 内暂停菜单面板从中心缩放弹出
- [ ] 暂停菜单打开时所有游戏计时冻结——战斗回合计时停止、动画暂停、音频暂停
- [ ] 「继续游戏」为默认焦点——按 Enter 或点击遮罩直接关闭暂停并恢复游戏
- [ ] 战斗中暂停时「保存并退出」按钮隐藏——战斗中不可存档
- [ ] 「返回主菜单」需二次确认——确认弹窗显示"未保存的进度将丢失"
- [ ] 「保存并退出」确认后正确写入存档文件（可验证：重启游戏 → 主菜单 → 继续游戏 → 回到暂停前的位置）
- [ ] 键盘导航：Tab 键按逻辑顺序到达所有按钮（继续→卡组→设置→保存→返回），Enter 激活焦点的按钮
- [ ] 战斗暂停 → 「查看卡组」进入只读模式——卡组可浏览但不可编辑、拖拽或移动卡牌

## 提交的无障碍等级 (Committed Accessibility Tier)

本项目的无障碍目标是 **WCAG-AA 基线**——确保核心游戏循环对所有玩家可及，而不显著增加 MVP 的实现复杂度。

| 维度 | 目标 | 依据 |
|------|:--:|------|
| 文本对比度 | 4.5:1（普通文本）/ 3:1（大文本 ≥18px） | WCAG 2.1 AA 1.4.3 |
| 键盘导航 | 所有可交互元素可通过键盘到达和激活 | WCAG 2.1 AA 2.1.1 |
| 焦点指示器 | 所有可聚焦元素有可见焦点边框（松石青 2px 光环） | WCAG 2.1 AA 2.4.7 |
| 独立于颜色的传达 | 任何仅靠颜色传达的信息必须有非颜色替代方案 | WCAG 2.1 AA 1.4.1 |
| 最小字号 | 交互文本 ≥ 13px，正文 ≥ 16px | 项目设计约束 |
| 手柄支持 | 部分——导航 + 确认/取消（非 MVP：无拖拽优化） | 项目平台约束 |
| 减少动态选项 | 全局开关——关闭循环动画，替换为静态颜色变化 | 晕动症 + 注意力保护 |
| 屏幕阅读器 | Godot 4.6 AccessKit 基础支持——关键状态变化播报 | 实现阶段评估可行性 |

## 超出范围的项（MVP 后）

| 功能 | 原因 |
|------|------|
| 触屏支持 | 目标平台为 PC Steam，非移动端 |
| 完整手柄支持（卡牌拖拽优化） | MVP 仅键盘/鼠标；手柄优化为打磨阶段任务 |
| 语音旁白 | 叙事文本量过大——超出 MVP 资源预算 |
| 高级色盲模式（完整调色板替换） | MVP 以形状+图标+文字冗余覆盖基础需求 |

## 逐屏幕无障碍要求

### 主菜单

- Tab 键按逻辑顺序遍历：新游戏 → 继续游戏 → 设置 → 退出
- 灰色禁用的「继续游戏」文字 ≥ 3:1 对比度
- 无存档时「继续游戏」通过灰色 + 文本不可用 + 无摘要行三重传达
- 减少动态模式下：背景层叠视差降为静态图，标题入场动画跳过

### HUD

- HP 条通过长度 + 数字 + 颜色三重编码——不依赖单一维度
- 卡牌费用不足通过灰度 40% + 不可拖拽双重传达
- 卡组超限通过红色闪烁 + 数字 + 文字标签三重传达
- 稀有度通过烟灰色阶边框 + 文字标签 + 图标数量复合编码（色盲兼容）
- 减少动态模式下：修为脉动、HP 闪烁、通知滑入全部替换为静态状态变化

### 暂停菜单

- 「返回主菜单」通过朱砂红边框 + ⚠ 图标 + 底部位置 + 分隔线四重传达
- 确认弹窗为认知障碍玩家提供容错——危险操作需二次确认
- 键盘焦点顺序：继续 → 查看卡组 → 系统设置 → 保存并退出 → 返回主菜单（战斗中跳过保存）

## 实现约束

1. **所有 Control 节点必须处理 Godot 4.6 双焦点系统**（鼠标焦点 ≠ 键盘焦点）。来源：ADR-0004 + engine-reference
2. **焦点光环复用**：松石青 2px 外部光环为所有可聚焦元素的统一焦点指示器——不每屏单独定义。来源：美术圣经 §7.4.1
3. **减少动态开关**：由「减少动态效果」全局开关驱动（设置 → 画面分类）。所有屏幕的动画行为必须检查此开关——参考各 UX 规范的 Transitions & Animations 部分
4. **色盲编码规则**：任何语义色彩必须有至少一个非颜色冗余通道（形状 / 图标 / 位置 / 文字 / 线宽）。来源：美术圣经原则 1「信息即颜色」
